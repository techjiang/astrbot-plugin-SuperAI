# v0.2.10 —— 图标令牌根因定位与兜底

**日期**：2026-09-27

## 主题

承接 v0.2.9：图标文件本身已无问题，但用户反馈**刷新后图标又变回默认星形**。
本轮定位到根因在 **AstrBot 框架侧**（图标 URL 走一次性令牌），
插件侧做「日志定位 + 上游修复材料」兜底。

## 症状

| 场景 | Logo 显示 |
| --- | --- |
| 刚装完，第一次打开插件列表 | ✅ 正常 |
| **刷新页面 / 重新进入 / 换设备** | ❌ 变成默认星形 |
| 静置超过 5 分钟 | ❌ 同样失效 |

## 根因

```
plugin_service.get_plugin_logo_token()  ->  _logo_cache 复用同一 token
file_token_service.handle_file()        ->  staged_files.pop(token)  取一次即删
file_token_service.check_token_expired()->  只看过期，看不出「已被取走」
```

实测（真实 AstrBot 源码）：同一令牌连续请求 5 次 → `[200, 404, 404, 404, 404]`。
叠加 `timeout=300`（5 分钟）后，即使不刷新也会过期。
前端 `ExtensionCard.vue` 的 `@error` 会把图标**永久**换成默认星形。

**这不是本插件的配置问题**：`logo.png` 是合法的 512×512 / 44 KB RGBA PNG，
GitHub 与商店 S3 两侧都返回 200，发布包内容也完整 —— 它只在**第一次**被成功取到。

## 本插件的动作

### 1. 兜底：把根因写进日志

`superai/assets.py::probe_logo_token_service()` 在启动时探测框架令牌语义，
命中即输出：

```
[SuperAI] 检测到框架图标令牌「一次性」问题（插件功能不受影响）：
  症状：刚装完第一次打开图标正常，刷新页面 / 重新进入 / 换设备后变成默认星形图标
  原因：<框架根因说明>
  修复：升级 AstrBot 到已修复该问题的版本；或临时用 Studio 面板查看状态
```

设计要点：按**行为**判断（不是 `inspect` 看签名）；同步 / 异步上下文均可；
独立线程执行不干扰调用方事件循环；失败优雅降级。

### 2. 上游材料：`docs/dev/upstream/`

- `astrbot-logo-token-fix.patch`：给 `FileTokenService` 增加 **reusable 令牌**，
  `plugin_service` 改用 `reusable=True` + 24h TTL。
  **默认仍为单次令牌** —— 聊天文件链接「取一次即失效」有安全语义，不能动。
- `README.md`：复现步骤、根因、修复思路、验证数据。

## 为什么插件不能自己修

插件列表卡片由框架渲染（`ExtensionCard.vue`），图标 URL 由框架的
`PluginService` 签发 —— 插件无法替换那段逻辑。因此本版本的定位是
**把根因暴露出来并推动上游修复**，而不是在插件里做无意义的绕过。

**最后核对**：`v0.2.10`（逐条对照真实 AstrBot 源码与测试断言，无凭空描述）
