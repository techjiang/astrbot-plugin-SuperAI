# v0.2.9 —— 图标解析与渲染修复

发布日期：2026-09-27

## 一句话

Issue #1 反馈「解析了，插件的 Logo 图标却不显示」。查下来的结论是：
**图标这条链路上有三件事是静默的** —— 文件找不到、文件太大、面板那条链路坏了，
全都不会报错，用户只看到「图标没出来」。

这一版把三件事都堵上了：缩小图标、加自检日志、把「框架只认一个文件名」钉死在测试里。

## 问题一：图标文件过大，弱网下就是「一直不显示」

`logo.png` 原本是 1024×1024 的 RGBA 位图：

```
raw pixel data : 1024 × 1024 × 4 = 4 MB
PNG on disk    : 636 KB
displayed at   : 列表里 40~80 px
```

关键在于 **AstrBot 商店详情页会把这个文件整份下载**。
文件越大，图片区域空着的时间越长 —— 弱网或移动端上，用户看到的就是
「图标一直没出来」，而不是「图标模糊」。

更麻烦的是当时的测试**奖励了这种做法**：

```python
assert width >= 256, "图标分辨率过低，商店卡片会糊"  # 只有下限，没有上限
assert size < 4 * 1024 * 1024  # 4 MB 实质上等于不设防
```

1024×1024 / 636 KB 完全满足这两条，于是「越大越好」被固化成了约定。

**修复**：按内容裁剪空白 → 归一化留白 → 缩到 512×512 → 量化 256 色。

```
logo.png        636 KB → 44 KB   （1/14）
studio/logo.png  22 KB →  7 KB
```

视觉校验：把新旧图贴到浅色（`#FFFFFF`）与深色（`#18181B`）背景上对比，
可见像素的平均色差 4.3/255、95 分位 12/255；全透明像素无 RGB 残留，
边缘不会渗色。

## 问题二：这条链路完全没有反馈，坏了查日志也查不到

框架侧写死的逻辑（`astrbot/core/star/star_manager.py`）：

```python
self.logo_fname = "logo.png"  # 只有一个文件名
logo_path = os.path.join(plugin_dir_path, self.logo_fname)
if os.path.exists(logo_path):  # 只探测一次
    metadata.logo_path = logo_path
```

找不到 → 静默回落默认图标，**一行日志都不打**。
找到 → 也不代表用户看得到（见问题一）。

**修复**：新增 `superai/assets.py`，插件启动时自检并写日志。

正常时一行：

```
[SuperAI] 图标自检通过 | /…/logo.png 512×512 44 KB
```

异常时逐条列出**症状 / 原因 / 修复**：

```
[SuperAI] 图标自检发现问题（不影响插件功能，但用户会看到异常）：
  1. 症状：弱网 / 移动端上图标长时间不显示（一直转圈）
     原因：图标 1024×1024、565 KB 过大；商店详情页会把这个文件整份下载下来，而它只显示几十像素
     修复：缩到 512×512 并压缩（推荐 256 色 PNG）
```

覆盖的故障形态：缺文件、放错目录、改名、非 PNG（SVG / JPEG 改扩展名）、
**文件截断**、过大、白底（无透明通道）、非正方形、面板图标缺失或过大。

两个设计约束：

- **不依赖 Pillow**。运行时只有 AstrBot 内置依赖，所以自己解析 PNG 的
  `IHDR`（宽高 / 色彩类型）、`tRNS`（调色板透明）、`IEND`（完整性）块。
- **只读、尽力而为**。任何异常都吞掉 —— 图标坏了不该影响插件功能。

## 问题三：文档把「只有一个文件名」写成了「按后缀回落」

`docs/install.md` 曾写：

```
logo.png  >  logo.jpg  >  logo.jpeg  >  logo.webp  >  logo.svg
```

真实框架里**没有这个列表**。这个错误不会让 CI 红，但会让维护者把美术资源
存成 `logo.jpg`，然后对着「图标不显示」反复排查。

**修复**：改为贴出真实源码，并补上「文件过大 → 一直加载不出来」这一行症状；
`docs/dev/astrbot-contracts.md` 同步修正，新增「运行时自检」一节。

## 测试（+19 项，另收紧 3 项）

新增 `tests/test_asset_health.py`：

- 每一种故障形态各一条断言（缺文件 / 放错目录 / 改名 / JPEG 冒充 PNG /
  文件截断 / 大位图 / 白底 / 非正方形 / 面板图标缺失与过大）；
- 报告必须带「症状 + 原因 + 修复」三件套；
- 自检**不得抛异常**（连插件目录都不存在时也要给可读结论）；
- 对着**真实框架源码**断言 `logo_fname == "logo.png"` 且源码里
  不出现 `logo.jpg` 等回落名 —— 框架若变了，文档与自检必须同步；
- 反向断言：文档里不得再出现不存在的回落列表。

收紧 `tests/test_logo_and_metadata.py`：分辨率由「≥ 256 且无上限」改为
「≥ 128 且 ≤ 512」；体积上限由 4 MB 收紧到 256 KB；新增「贴到浅色 / 深色底
都必须清晰可见」的渲染安全断言。

`scripts/e2e_smoke.py` 补图标尺寸 / 体积校验，并复用插件自检逻辑跑一遍真实仓库。

具体症状，确认这些闸门真的有效（而不是恒真）。
