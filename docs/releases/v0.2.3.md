# v0.2.3 —— 首个正式 Release

发布日期：2026-09-27

## 一句话

修掉 4 个「不报错、不崩溃、但功能静默失效」的真实缺陷，并补齐文档体系。

## 修复

### 1. `/superai memory` 四个子指令整体不可达

插件里同时存在用 `@filter.command_group("superai.memory")` 注册的**指令组**
与 `@superai_group.command("memory")` 注册的**同名兼容命令**。
框架对两者的匹配语义并不互斥（都是 `startswith`），
只要消息以 `superai memory` 开头，两个 handler 都会命中，
兼容命令先把事件消费掉，子指令组里的实现**一次都执行不到**，且整条链路一句错都不报。

现在 `memory` 是挂在 `superai` 下的**真子组**（`@superai_group.group("memory")`），
并删除了同名兼容命令。

### 2. 工具与插件的归属关系断裂

`Context.add_llm_tools()` 从工具类的 `__module__` 反推归属，得到顶层模块名
`superai.tools.xxx`，既不在 `star_map` 也不等于入口模块路径，
于是 `PluginManager._is_plugin_llm_tool()` 一律返回 `False` ——
仪表盘停用 / 卸载插件时这些工具**不会被一起停掉**，重载也不刷新 `active`。

现在在 `add_llm_tools()` **之后**调用 `_claim_tools()` 把归属统一改写为
插件入口模块路径，并在 `initialize()` 里再兜一次。

### 3. 被拒绝的请求会污染耗时统计

三条提前返回路径（群被拒 / 任务类型未启用 / 预算拦截）只往
`_request_started` 里压、从不弹出，等真正统计时取到的是几小时前的时间戳，
「平均耗时」彻底失真。

现在压栈动作移到所有提前 `return` 之后，预算拦截路径显式回收，
并新增 `REQUEST_STARTED_MAX_AGE`（1 小时）丢弃过期残留。

### 4. 只配一个默认模型的用户，摘要与自动事实抽取静默失效

「轻量任务」的候选链原本只有「摘要专用 → `cheap` → `strong`」，
只配默认模型时是**空列表**，`agent.simple()` 立刻抛
`ProviderUnavailableError` 并被吞掉，表现为两个主打功能一个都不工作，
日志里只有一行「没有可用的模型提供商」。

现在 `resolve_light_candidates()` 会兜底到「会话 / 全局默认模型」；
配了档位则仍优先用档位，不抢用户配置。

## 增强

- `/superai route` 的降级链预览跟随**当前生效档位**（原先硬编码用 `strong`）；
- Studio 面板与 `/tools` 接口带上工具中文用途说明；
- 文档体系：新增「使用文档 / 开发文档 / 契约文档」，
  并提供本发布说明归档。

## 升级注意

- 若你曾依赖 `/superai memory` 的旧兼容命令行为，请改用四个子指令
  （`list` / `search` / `clear` / `stats`，行为一致）；
- 无破坏性配置变更，升级后直接重载插件即可。
