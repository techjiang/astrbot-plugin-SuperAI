# v0.2.6 —— 修正商店作者信息 + Logo 解析链路固证

发布日期：2026-09-27

## 一句话

修掉「商店卡片上作者显示成平台账号」的信息错误，并把插件 Logo 的整条解析链路
（放哪、叫什么、什么格式、能不能解码）用测试固定下来。

## 修复

### 1. 市场卡片上的作者显示成了平台账号

AstrBot 插件市场的卡片直接读 `metadata.yaml` 的 `author` 字段。
此前它是平台账号 `cosc`，于是商店里显示「作者：cosc」，
而真正的插件作者「科技酱」只出现在 README 里 —— 两处说法打架，
用户按商店信息根本找不到作者。

现在统一为作者「科技酱」的**包身份** `TechSauce`：

```yaml
author: TechSauce
```

README 的「关于作者」章节同时写明展示名与包身份，并解释为什么两者不同：

- **展示名**：`科技酱` —— 市场卡片与文档里给人看的名字；
- **包身份**：`TechSauce` —— 代码里的稳定标识，不含空格与中文。

### 2. Logo 的解析链路此前没有任何测试守住

框架不会主动去找图片。`PluginManager._get_plugin_logo()` 在插件目录
**根下**按固定顺序做一次存在性探测：

```
logo.png  >  logo.jpg  >  logo.jpeg  >  logo.webp  >  logo.svg
```

找不到就回落到默认图标，**一条日志都不打**。下面这几类问题因此都只能
等用户反馈，本地测试永远发现不了：

| 现象 | 原因 |
| --- | --- |
| 显示默认图标 | `logo.png` 不在插件根目录下 |
| 显示默认图标 | 文件被改名（`Logo.PNG`、`icon.png`） |
| 破图 / 空白 | 文件名是 `logo.png`，内容其实是 SVG 或 JPEG |
| 边缘白毛刺 | 用了白底图，不是透明背景图 |

现在这四类问题各有对应断言，见下。

## 增强

### 新增 `tests/test_logo_and_metadata.py`（21 项契约测试）

**Logo 解析链路**

- 图标落在框架查找路径上，且首选 `logo.png`；
- 文件名后缀与**真实图片格式**一致 —— 禁止「JPEG 改名 PNG」「SVG 改名 PNG」，
  后者会让浏览器 `<img>` 直接不显示；
- Pillow 能解码；正方形；分辨率 ≥ 256（商店卡片会放大显示）；
- **全透明像素占比 ≥ 20%** —— 白底图的全透明像素为 0，这条能把它拦下来；
- PNG 结构完整：`IHDR` 在最前、长度 13、`IEND` 存在且 CRC 正确
  （`Image.open` 对截断文件有容错，前端解码器没有）；
- 插件根目录不留多份图标变体，避免「改了 `logo.png`，实际显示 `logo.svg`」；
- 面板图标是同一份美术资源的缩放版，且也是真 PNG + 透明背景；
- `pages/studio/index.html` 引用的文件确实存在。

**商店元数据**

- `author` 是**插件作者**而不是平台账号，且与 README「关于作者」章节一致；
- `display_name` / `short_desc` / `desc` 类型正确、长度在商店可接受区间；
- `tags` 非空、无重复、无空白项、数量适中；
- `repo` / `social_link` 是干净的 HTTPS 地址（无 query / fragment / 空格）；
- `repo` 指向插件的发布仓库；
- 版本号是纯三段式语义化版本（预发布后缀会让商店更新检测行为不可预期）；
- `metadata.yaml` 无 Tab 缩进、使用 LF 换行。

### 文档

## 说明

`author` 参与 `plugin_id = author + "/" + name`，是插件在市场里的全局唯一标识，
也是老用户匹配更新的依据。本次修正发生在插件尚未通过市场审核、
**没有存量用户**之前；发布之后不得再改 —— 改了老用户会收不到更新，
只能重新安装。测试与文档里都写明了这条约束。

**无破坏性变更**：配置项、数据格式、指令签名与 v0.2.5 完全一致。
