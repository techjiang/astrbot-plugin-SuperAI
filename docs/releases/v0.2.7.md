# v0.2.7 —— 配置健壮性与统计口径修正

发布日期：2026-09-27

## 一句话

修掉 5 处「不报错、不崩溃，但功能静默失效」的真实问题：其中一类会让
**每一条消息**的钩子都抛异常（路由 / 记忆 / 预算因此全部失效），
另一类会让「最近 7 天」的用量统计**跨月取数**。

## 背景

AstrBot 的 `_conf_schema.json` **只用来生成默认值** —— 它不对用户在
WebUI 里保存的值做任何类型校验或强制转换
（见 `AstrBotConfig.check_config_integrity()`：只补缺失项、对齐键顺序）。
因此把数字字段填成 `64k`、`三十天` 这类值会**原样**进入插件配置。

插件里有一批 `int(cfg.get(...))` / `float(cfg.get(...))` 直接转换，
只要命中非数字就会抛异常。此前没有任何测试守住这一点。

## 修复

### 1. 数字配置项填错，插件每轮静默失效（最严重）

`on_llm_request` 里有 `threshold = int(self.config.router.get("long_context_tokens") or 64000)`。
这行在**每条消息**上执行：

```python
ValueError: invalid literal for int() with base 10: '64k'
```

异常被框架的 `call_event_hook()` 捕获并只打一段 traceback（见
`astrbot/core/pipeline/context_utils.py`），**插件看起来「加载成功」**，
但路由、记忆注入、预算拦截全部不再生效。

在 `__init__` 路径上更直接：`max_steps` / `retention_days` 填成非数字时
插件**加载失败**，被 `PluginManager` 记进 `failed_plugin_dict`。

修复：所有面向用户配置的数字转换统一走
[`as_int` / `as_float`](../../superai/core/utils.py)（容错解析 + 区间夹紧），
共覆盖 11 处调用点。

### 2. 「最近 N 天」统计实际跨月取数

`MetricsCollector.range_stats()` 此前是 `sorted(self._days)[-N:]` ——
取的是「最近 N 个**有数据的日期**」，不是自然日区间。
只要日期有断档（用户停用几天 / 机器关机 / `retention_days` 调大后重新统计）：

```
range_stats(7) -> ['2026-03-11', '2026-09-27']
```

于是 `/superai stats 7`、Studio 面板与 `summary()` 会把半年前的用量
算进「最近 7 天」，数字凭空翻倍，界面上完全看不出异常。

修复：按自然日补全区间，区间内没有数据的日期返回**临时空桶**
（不写入 `_days`，避免挤占 `retention_days` 名额），
趋势的 x 轴因此是完整时间轴。

### 3. 知识库工具丢弃本可用的检索结果

`retrieve_kb()` 里对相关度解析了两次，第二次写成了裸
`float(item.get("score") or 0)`。上游（第三方 rerank / 稀疏检索器）
给出非数字相关度时：

```
工具 superai_knowledge_search 执行失败：could not convert string to float: 'high'
```

**检索到的内容被整段丢弃**。修复：只解析一次并复用结果，
非数字降级为 `0.00`，内容照常返回。

### 4. 联网搜索的配置错误与 JSON 解析失败会穿透

`WebSearchTool.run_tool()` 只捕获 `aiohttp.ClientError` / `TimeoutError`：

- 选了 `searxng` 却没填地址 → `ValueError` 穿透；
- 超时字段填成非数字 → `float()` 抛异常；
- SearXNG 被反代拦截返回 HTML → `json()` 抛 `JSONDecodeError`。

现在全部转成用户可读的文本提示，工具不再因配置问题失控。

### 5. 网络抓取工具的同类问题

`FetchUrlTool` 的 `timeout` / `max_chars` 同样来自配置，
统一改用 `as_float` / `as_int`。

| `tests/test_config_robustness.py` | 12 | 配置读取必须容错；用 **AST/正则扫描源码**，任何新的裸 `int(cfg.get(...))` 都会被 CI 拦下 |

它不测行为，而是扫描全部插件源码，因此这类问题无法「换个写法」再溜进来。

## 无破坏性变更

配置项、数据格式、指令签名与 v0.2.6 完全一致。统计口径的修正会让
「最近 N 天」的数字**变小**（此前含区间外数据），这是预期行为。
