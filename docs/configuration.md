# 配置手册

配置在 AstrBot WebUI → 插件管理 → SuperAI → 配置 中可视化编辑，
配置模式定义在仓库根目录的 [`_conf_schema.json`](../_conf_schema.json)。

下面按配置分组逐项说明。**「默认」列即 schema 里的 `default`。**

## 基础

| 配置项 | 类型 | 默认 | 说明 |
| --- | --- | --- | --- |
| 启用 SuperAI 增强 | bool | `true` | 总开关。关闭后钩子与指令直接跳过，不影响 AstrBot 原流程 |
| 启用增强的任务类型 | list | `chat, agent, long_context, image` | 只有命中白名单的请求才会被 SuperAI 接管。`chat`=普通对话，`agent`=工具调用链路，`long_context`=上下文超阈值，`image`=带图片/语音 |
| 调试日志 | bool | `false` | 输出路由决策、记忆命中、工具装配等详细日志 |

> `image` 一定要留在白名单里，否则「有图片就走视觉档」的能力等于关闭。

## 模型路由（SuperRouter）

| 配置项 | 类型 | 默认 | 说明 |
| --- | --- | --- | --- |
| 启用模型路由 | bool | `true` | 关闭后所有请求都走会话默认模型 |
| 路由策略 | enum | `rule` | `rule` 规则优先 / `auto` 智能启发式 / `cheap_first` 优先省钱 / `quality_first` 优先质量 |
| 失败自动降级 | bool | `true` | 主模型失败时按降级链换模型重试 |
| 最大重试次数 | int | `2` | 降级链最多额外尝试的模型数，单次请求最多尝试 `max_retries + 1` 个模型 |
| 单次请求超时（秒） | int | `120` | 超时即视为失败，换下一个候选模型 |
| 低成本模型 | provider | 空 | 闲聊、翻译、改写等简单请求 |
| 高质量模型 | provider | 空 | 写作、代码、总结等需要输出质量的请求 |
| 推理模型 | provider | 空 | 数学、逻辑、排错等需要深度思考的请求 |
| 视觉模型 | provider | 空 | 带图片的请求 |
| 长上下文模型 | provider | 空 | 超长上下文请求 |
| 长上下文阈值（tokens） | int | `64000` | 估算上下文超过该值切到长上下文档 |
| 自定义关键词路由 | dict | `{}` | 键=关键词，值=档位；命中即切到该档位，优先于内置关键词表 |

**留空 = 该档位不启用**。所有档位都留空也完全可用，路由会回落到会话默认模型。

推荐的最小配置：

- 只想要「省钱」：`低成本模型` 填便宜模型，策略选 `cheap_first`；
- 想要「该省则省、该强则强」：`低成本模型` + `高质量模型`，策略选 `rule`；
- 想要「永远不失败」：多填几个档位，`失败自动降级` 打开。

细节见 [模型路由](./routing.md)。

## 记忆与摘要（SuperMemory）

| 配置项 | 类型 | 默认 | 说明 |
| --- | --- | --- | --- |
| 启用记忆增强 | bool | `true` | 记忆功能总开关 |
| 自动生成对话摘要 | bool | `true` | 超过触发轮数后用轻量模型压缩历史 |
| 摘要触发轮数 | int | `12` | 距上次摘要累计超过该轮数就压缩一次（下限 4） |
| 摘要专用模型 | provider | 空 | 留空则用「低成本模型」档；建议用便宜的小模型 |
| 摘要最大长度（字） | int | `600` | 摘要正文上限（下限 80） |
| 启用长期记忆 | bool | `true` | 自动抽取偏好与事实，并在后续对话注入 |
| 记忆注入条数 | int | `5` | 每轮最多注入多少条相关记忆（上限 20，实际注入上限 8） |
| 自动抽取事实 | bool | `true` | 关闭后只能靠模型调用工具或用户显式「记住」来写入 |
| 把记忆注入提示词 | bool | `true` | 关闭后记忆只在模型主动调用 `superai_recall` 时使用 |
| 记忆权重半衰期（天） | int | `30` | 长时间未命中的记忆按半衰期衰减，权重低于 0.2 时清理 |

细节见 [记忆与摘要](./memory.md)。

## 联网搜索

| 配置项 | 类型 | 默认 | 说明 |
| --- | --- | --- | --- |
| 启用联网搜索 | bool | `false` | 开启后注册 `superai_web_search` / `superai_fetch_url` |
| 搜索引擎 | enum | `duckduckgo` | `duckduckgo`（免 Key）/ `searxng`（自建） |
| SearXNG 实例地址 | string | 空 | 例如 `https://searx.example.com`，需开启 JSON 输出 |
| 搜索服务 API Key | string | 空 | 仅自建实例需要鉴权时填写 |
| 返回结果条数 | int | `5` | |
| 超时（秒） | int | `15` | |

> 默认引擎走 DuckDuckGo HTML 端点，无需 Key，但受网络环境影响较大。
> 生产环境建议自建 SearXNG。

## 知识库增强

| 配置项 | 类型 | 默认 | 说明 |
| --- | --- | --- | --- |
| 启用知识库工具 | bool | `false` | 开启后注册 `superai_knowledge_search` |
| 默认知识库 | list | `[]` | 模型调用检索工具且未指定知识库时使用 |
| 自动检索并注入知识库 | bool | `false` | 每轮对话都用用户问题检索知识库并注入片段，**会增加一次检索开销与少量 token** |
| 检索条数 | int | `5` | |
| 最低相关度阈值 | float | `0.0` | 低于阈值的片段被丢弃；`0` 表示不过滤 |

## Agent 设定

| 配置项 | 类型 | 默认 | 说明 |
| --- | --- | --- | --- |
| 启用 Agent 工具调用 | bool | `true` | 关闭后 `/ai` 只做纯文本生成 |
| 最大工具调用步数 | int | `12` | 单轮对话最多几步工具调用 |
| 工具调用超时（秒） | int | `60` | |
| 附加系统提示词 | text | 空 | 追加到 `system_prompt`，用于设定角色与风格 |

> 附加系统提示词会**追加**到 AstrBot 原有的 system prompt 之后，不会覆盖。
> 它是稳定内容，不随轮次变化，因此不会破坏提示词缓存。

## 指令行为

| 配置项 | 类型 | 默认 | 说明 |
| --- | --- | --- | --- |
| 允许使用的群 | list | `[]` | 留空 = 所有群允许 |
| 禁止使用的群 | list | `[]` | 优先级高于允许列表 |
| 指令冷却（秒） | int | `3` | 同一会话两次 `/ai` 的最小间隔 |
| 单次输入上限（字符） | int | `4000` | 超长输入会被截断 |

> 黑白名单只对**群聊**生效，私聊始终允许。

## 用量统计与配额

| 配置项 | 类型 | 默认 | 说明 |
| --- | --- | --- | --- |
| 启用用量统计 | bool | `true` | |
| 每日 Token 上限 | int | `0` | 0 = 不限制，超限直接拦截并提示 |
| 每日请求数上限 | int | `0` | 0 = 不限制 |
| 统计数据保留天数 | int | `30` | 超过天数的日聚合数据会被清理 |

细节见 [用量统计与成本控制](./usage-and-budget.md)。

## 工作流编排

| 配置项 | 类型 | 默认 | 说明 |
| --- | --- | --- | --- |
| 启用工作流 | bool | `true` | |
| 单个工作流最大步数 | int | `8` | 超出部分在载入时被截断 |
| 单步输出上限（字符） | int | `4000` | 每步结果返回时的裁剪长度（下限 200） |
| 工作流定义 | dict | `{}` | 见下方示例 |

```json
{
  "早报": {
    "description": "每日科技早报",
    "route": "cheap",
    "steps": [
      { "name": "收集", "prompt": "用三句话总结今天的科技新闻" },
      { "name": "翻译", "prompt": "把下面内容翻译成英文：\n{{prev}}" }
    ]
  }
}
```

细节见 [工具与工作流](./tools-and-workflows.md)。
