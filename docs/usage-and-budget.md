# 用量统计与成本控制

## 统计口径

每次请求会记录：

- 会话（`unified_msg_origin`）
- provider id
- 命中的路由档位
- 输入 / 输出 / 命中缓存的 token 数
- 耗时（ms）
- 成功还是失败

数据按**天**聚合，保留 `统计数据保留天数`（默认 30）天，
落盘在 `data/plugin_data/astrbot_plugin_superai/metrics.json`。

两条链路都会记：

- **AstrBot 默认管线**：`on_llm_response` 钩子记录真实 token 用量；
- **`/ai` 指令**：SuperAI 自己发起调用，不会触发该钩子，
  因此由 `AgentOutcome` 带回真实 token 后显式记录
  （早前只记「1 次请求」不记 token，导致按 token 计的配额在指令路径上形同虚设）。

## 平均耗时怎么算

每轮的起始时间在 `on_llm_request` 里记录，在 `on_llm_response` 里弹出配对。

两个防坑措施：

1. 记录动作放在**所有提前 return 之后**（群被拒、任务类型未启用、预算拦截都不记），
   否则只进不出会泄漏记录，等到统计时拿到几小时前的时间戳，平均耗时算成**几小时**；
2. `REQUEST_STARTED_MAX_AGE`（1 小时）：超过 1 小时的残留记录直接丢弃，
   即使将来又出现没配对的路径，也算不出荒谬数字。

## 每日配额

配置项：`用量统计与配额`。

| 配置项 | 说明 |
| --- | --- |
| 每日 Token 上限 | 0 = 不限制；达到后 SuperAI 拦截请求并提示 |
| 每日请求数上限 | 同上 |

拦截发生在 `on_llm_request` 的最前面（在记忆/路由之前），
用户会直接收到提示话术，而不是让请求打到模型后再失败。

配额对**当天**计数，跨天自动清零。

## 查看用量

```
/superai stats        # 最近 7 天
/superai stats 30     # 最近 30 天（1–90）
```

输出包含：请求数（含失败数）、输入/输出/缓存命中 token、平均耗时、
模型调用分布、路由分布、当日配额使用情况。

Studio 面板的「用量统计」区块还会画近 7 天的柱状图（按模型 / 按路由 / 按天）。

## 省钱的几个旋钮

| 手段 | 配置 |
| --- | --- |
| 让闲聊走便宜模型 | `路由策略 = rule` + 配好 `低成本模型`，或直接 `cheap_first` |
| 压缩长历史 | 打开 `自动生成对话摘要`，把 `摘要触发轮数` 调小 |
| 摘要用便宜模型 | `摘要专用模型` 指定一个小模型 |
| 少注入记忆 | 调小 `记忆注入条数` |
| 关掉自动知识库注入 | `自动检索并注入知识库 = false`（默认就是关） |
| 限制单次上下文 | 调小 `长上下文阈值`，让长请求走更省的长窗模型 |
| 硬上限 | 设置 `每日 Token 上限` / `每日请求数上限` |

## 其他开销说明

- **事实抽取**：每 180 秒最多一次，且同一段对话不会重复抽；
- **滚动摘要**：每累计 `摘要触发轮数` 才压缩一次，失败时会推进进度避免每轮重试；
- **记忆维护**：每 600 秒一次，只做内存内权重计算与一次落盘。
