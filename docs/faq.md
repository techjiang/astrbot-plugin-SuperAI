# 常见问题与排错

排查通用套路：**先开 `调试日志`，再看 `/superai status` 的「钩子」一行**，
然后看 AstrBot 日志里有没有 `[SuperAI]` 开头的 error。

---

## 插件装了，但完全没反应

按顺序检查：

### 1. 入口文件位置对不对

AstrBot 的 `PluginManager` **只认**插件目录下的 `main.py` 或「与目录同名的
`<dirname>.py`」。如果日志里出现

```
Plugin astrbot_plugin_superai has neither main.py nor astrbot_plugin_superai.py; skipping it.
```

说明入口没被找到 —— 整个插件被静默跳过，插件列表里可能仍然显示「已安装」。

解决：确认 `data/plugins/astrbot_plugin_superai/main.py` 存在（不是软链接，
也没有多套一层目录）。

### 2. 有没有 `TypeError: ... missing 1 required positional argument`

日志里如果有：

```
TypeError: SuperAIPlugin.on_llm_request() missing 1 required positional argument: 'req'
```

说明插件类的 `self` 绑定失败（钩子定义在子模块，与入口模块路径不一致）。
这个异常会被框架的 `call_event_hook()` 吞掉，只留一行 error，
表现就是「路由、记忆注入、图片保护、预算拦截全部静默失效」。

v0.2.1 之前有这个 Bug，升到最新版即可。

### 3. 总开关与任务白名单

- `启用 SuperAI 增强` 是否为 `true`；
- `启用增强的任务类型` 是否包含你正在用的类型
  （尤其 `image` —— 不在白名单里时带图请求完全不走 SuperAI）。

### 4. 群权限

`禁止使用的群` 里的群**完全不生效**（连回复都没有）；
`允许使用的群` 非空时，只有列表内的群可用。私聊不受限制。

### 5. 钩子未就绪

`/superai status` 显示 `钩子：⚠️ 未检测到`，或 Studio 面板
`hooks_ready: false` → 回到第 1、2 条排查。这是最需要重视的一种状态：
**插件看起来一切正常，但实际什么都没做。**

---

## 一直走同一个模型 / 路由没生效

1. `模型路由 → 启用模型路由` 是否打开；
2. 对应档位是否**真的填了模型**（留空 = 该档位不启用）；
3. 该请求的任务类型在不在 `启用增强的任务类型` 里；
4. 开 `调试日志`，看日志里的这一行：

   ```
   [SuperAI] 路由档位=cheap 主模型=xxx 原因=命中闲聊关键词 降级链=[...]
   ```

   - 原因是「未命中规则，使用会话默认模型」→ 换策略或加 `自定义关键词路由`；
   - 原因是「路由未启用」→ 打开开关；
   - **压根没有这一行** → 请求没被 SuperAI 接管，回到上一节排查。

5. 检查是否用 `/superai route` 把会话固定到某个档位了（`/superai route auto` 恢复）。

---

## 摘要不生成 / 记忆不写

这两种情况通常是**轻量模型候选链为空**导致的。修复后（v0.2.3 起）会自动兜底到
「会话 / 全局默认模型」，所以先确认版本。

如果仍不生成：

| 现象 | 检查 |
| --- | --- |
| 摘要一直为空 | `自动生成对话摘要` 是否开启；累计轮数是否已达 `摘要触发轮数`（默认 12 条） |
| 日志有「生成摘要失败：没有可用的模型提供商」 | 「服务提供商」里至少启用一个对话模型 |
| 记忆列表为空 | `启用长期记忆` 是否开启；对话内容是否太短（< 20 字不抽取） |
| 抽取从不触发 | 事实抽取有 180 秒节流，且同一段对话不会重复抽；多聊几轮再看 |
| 模型没调用 `superai_remember` | `启用 Agent 工具调用` 是否开启；`/superai tools` 里有没有该工具 |

---

## `/superai memory` 子指令没反应

v0.2.3 之前，`memory` 同时注册为「指令组」与「同名兼容命令」，
AstrBot 的 `startswith` 匹配语义不互斥，导致 `/superai memory list|search|clear|stats`
全部被兼容命令抢走、**整条链路一句错都不报**。

升级到 v0.2.3+ 即可。当前版本 `memory` 是 `superai` 下的真子组
（`@superai_group.group("memory")`），四个子指令都正常。

---

## 面板打不开 / 一片空白

1. 确认 AstrBot WebUI → 插件 → SuperAI 下能看到 `SuperAI Studio` 入口；
2. 打开浏览器控制台看是哪个 API 报错，逐个请求：
   - `/{PLUGIN_NAME}/status`
   - `/{PLUGIN_NAME}/stats?days=7`
   - `/{PLUGIN_NAME}/sessions`
3. 插件日志里会有 `[SuperAI] xxx API 失败：...`；
4. 面板区块显示 ❌ 只是「该能力没开」，不是错误（例如没配联网就显示 ❌）。

---

## 平均耗时显示成几小时

v0.2.3 之前存在「被拒绝的请求只进不出地泄漏起始时间」的 Bug
（群被拒 / 任务未启用 / 预算拦截三条路径），导致取到很久以前的时间戳。

升级到 v0.2.3+ 即可，同时新增了 1 小时的有效期上限，即使将来又出现没配对的
路径也不会算出荒谬数字。

---

## 停用插件后工具还在

工具类的 `__module__` 会让框架反推出「顶层模块名」归属，
导致 `_is_plugin_llm_tool()` 返回 `False`，停用/卸载插件时工具不被一起停掉。

v0.2.3 起插件会把工具归属改写成入口模块路径。若仍有问题，重载一次插件。

---

## 联网搜索失败 / 结果为空

- 默认 DuckDuckGo HTML 端点**无需 Key**，但受网络环境影响，可能被限流；
- 生产环境建议自建 SearXNG 并在配置里切换（需开启 JSON 输出）；
- 确认 `联网搜索 → 启用` 已打开，且 `/superai tools` 里有 `superai_web_search`。

---

## 知识库检索不到内容

1. `知识库增强 → 启用知识库工具` 是否开启；
2. `默认知识库` 是否选了至少一个（**没选知识库时工具根本不会注册**）；
3. `最低相关度阈值` 设得太高会过滤掉全部结果，先设 `0`；
4. 相关日志：`[SuperAI] 知识库检索失败：...`。

---

## 工作流跑不起来

| 现象 | 检查 |
| --- | --- |
| 「当前没有配置任何工作流」 | `工作流定义` 是否为合法 JSON 对象 |
| 「未找到工作流 xxx」 | 名称大小写与配置里的键是否一致（区分大小写） |
| 「没有可用的模型提供商」 | 「服务提供商」里至少启用一个对话模型 |
| 步骤被截断 | 每个工作流最多 `单个工作流最大步数` 步（默认 8），超出部分载入时被丢掉 |
| 输出太短 | `单步输出上限`（默认 4000 字符） |

---

## 升级后行为变了

升级后请对照 [CHANGELOG.md](../CHANGELOG.md)。例如 v0.2.3：

- 移除了 `/superai memory` 的同名兼容命令（改用子指令组）；
- `/superai route` 预览的降级链改为跟随当前生效档位。

---

## 还是不行，怎么反馈

提 Issue 时请带上：

1. AstrBot 版本 + SuperAI 版本（`/superai status` 第一行）；
2. `/superai status` 与 `/superai route` 的完整输出；
3. 开启调试日志后的相关日志片段（**请脱敏** provider key 等敏感信息）；
4. 复现步骤与预期行为。

见 [贡献指南](../CONTRIBUTING.md#反馈问题)。
