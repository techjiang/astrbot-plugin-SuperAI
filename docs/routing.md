# 模型路由 SuperRouter

## 它解决什么

一个 Bot 通常配了好几个模型（便宜的、强的、支持视觉的），但 AstrBot 默认
**只会用「当前使用」的那一个** —— 说一句「你好」也走最贵的模型；
主模型超时/限流时整轮对话直接失败。

SuperRouter 在 `on_llm_request` 钩子上做一次决策：按「任务类型 + 消息内容 +
上下文长度 + 会话偏好」把本轮请求交给最合适的模型；失败时按降级链换模型重试，
并把连续失败的模型自动排到后面。

## 五个档位

| 档位 | 适用场景 | 建议模型 |
| --- | --- | --- |
| `cheap` | 闲聊、问候、翻译、改写 | 便宜的小模型 |
| `strong` | 写作、总结、代码、方案 | 主力质量模型 |
| `reasoning` | 数学、逻辑、排错、推导 | 推理模型 |
| `vision` | 带图片的请求 | 多模态模型 |
| `long_context` | 超长上下文 | 长窗口模型 |
| `default` | 未命中任何规则 | 会话当前模型 |

`default` 不需要配置，它就是「沿用会话当前模型」。任何档位留空都表示不启用该档位。

## 四种策略

配置项：`模型路由 → 路由策略`。

| 策略 | 行为 |
| --- | --- |
| `rule`（默认） | 先查**自定义关键词映射**，再查内置关键词表（推理 / 高质量 / 闲聊 / 图片描述） |
| `auto` | 不看关键词表，按内容长度与特征启发式判断 |
| `cheap_first` | 一律走 `cheap` |
| `quality_first` | 一律走 `strong` |

### 决策顺序（无论哪种策略都先执行的前置判断）

1. **会话固定档位**：用户用过 `/superai route strong` 时直接用它，其余规则全部跳过；
2. **有图片** → `vision`；
3. **上下文 token 数 >= `long_context_tokens`** → `long_context`；
4. 之后才进入策略分支（`cheap_first` / `quality_first` 在此直接返回）。

`auto` 策略下的启发式顺序：

1. 命中推理关键词 → `reasoning`；
2. 输入 >= 800 tokens → `strong`；
3. 输入 <= 24 tokens 且命中闲聊关键词 → `cheap`；
4. 否则 → `default`。

### 内置关键词表（节选）

- 推理：`证明` `推导` `为什么` `计算` `算法` `复杂度` `报错` `traceback` `debug` `step by step` …
- 高质量：`写一篇` `帮我写` `总结` `翻译` `润色` `代码` `重构` `方案` `报告` …
- 闲聊：`你好` `在吗` `早上好` `晚安` `哈哈` `谢谢` `hi` `hello` …
- 联网（用于提示模型主动搜索）: `最新` `今天` `实时` `新闻` `股价` `天气` `latest` `news` …

关键词表在 `superai/router/router.py` 顶部定义。

## 自定义关键词路由

配置项：`自定义关键词路由`（dict）。

```json
{
  "早报": "cheap",
  "部署": "strong",
  "算一下": "reasoning",
  "看下这张": "vision"
}
```

- 键 = 关键词（大小写不敏感，做子串匹配），值 = 档位；
- 命中即返回，**优先于内置关键词表**；
- 值不是合法档位时会退化为 `strong`。

## 降级链与健康度

### 降级链怎么拼

主模型（当前档位配的模型）在最前，之后依次追加
`strong → cheap → reasoning → long_context` 中**真正配了模型**的档位，去重。
若档位模型一个都没配，则回落到**会话当前模型**。

最终链长度 = `1 + 最大重试次数`（`失败自动降级` 关闭时为 1）。

### 健康度排序

- 某 provider 连续失败达到 **2 次**即被标记为「不健康」，在候选链里被排到最后；
- 一次成功即清零失败计数；
- 失败记录 **30 分钟**后自动过期，避免旧故障长期拖累排序；
- 如果**所有**候选都不健康，仍然正常尝试（不会因为「全都病了」而彻底不可用）。

健康度落盘在 `data/plugin_data/astrbot_plugin_superai/router.json`，重启后仍有效。

在 Studio 面板的「模型健康度」区块或 `/superai route` 都能看到失败计数。

### 超时与重试

- 单次模型调用超过 `单次请求超时`（默认 120s）即视为失败，换下一个候选；
- 候选全部失败时抛 `ProviderUnavailableError`，`/ai` 会返回
  「所有候选模型都调用失败」，并在 hint 里带上最近一次错误。

## 会话级临时覆盖

```
/superai route reasoning    # 本会话固定走推理模型
/superai route auto         # 恢复自动路由
```

只影响当前会话（按 `unified_msg_origin` 区分），**不写配置文件**，
重启后全部恢复自动。适合调试，也适合「这个群专门用来写代码」这类场景。

## 常见误区

- **「我配了档位但还是走默认模型」**：检查对应档位是否填了模型，
  以及该请求的任务类型是否在 `启用增强的任务类型` 白名单里。
- **「闲聊没走便宜模型」**：`rule` 策略下只有**短**闲聊（<= 30 字）才命中 `cheap`；
  长文本会被判定为需要质量输出。想让所有请求都走便宜的，用 `cheap_first`。
- **「`/superai route` 显示的链和实际不一样」**：v0.2.3 起预览链已跟随当前生效档位，
  若仍不符请升级插件。
- **「`vision` 档没生效」**：确认 `image` 在任务白名单里，且该请求确实带图。
