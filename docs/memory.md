# 记忆与摘要 SuperMemory

SuperMemory 包含两条互相独立的能力：

- **滚动摘要**：把过长的历史压缩成一段摘要，控制 token 成本；
- **长期记忆**：抽取稳定偏好与客观事实，在后续对话里按相关性注入。

两者都按会话（`unified_msg_origin`）隔离，不同群/私聊互不串味。

## 滚动摘要

### 触发条件

累计轮数（`summary.json` 里的 `total_rounds`）距上次摘要超过
`摘要触发轮数`（默认 12，下限 4）时，取最近一段人类可读历史交给轻量模型压缩。

摘要正文上限 `摘要最大长度`（默认 600 字），下限 80。

### 用哪个模型

「轻量任务」的候选链（`MemoryService.resolve_light_candidates`）：

```
摘要专用模型 → cheap 档 → strong 档 → 会话/全局默认模型
```

最后一档兜底很关键：**只配了一个默认模型的用户**（最常见的部署方式）
此前会拿到空候选链，导致摘要与事实抽取静默失效。

### 摘要失败怎么办

摘要调用失败时不会影响对话，只会：

1. 记一行 warning；
2. 把「已覆盖轮数」推进到 `total_rounds - 触发轮数`，
   避免下一轮又立刻重试、持续烧钱。

### 摘要有什么用

- 长对话不再无限膨胀，早期结论仍能保留；
- 摘要以 `<history_summary>` 区块注入本轮上下文（**仅本轮有效**，不写进会话历史）；
- 模型也可以通过 `superai_history_summary` 工具主动读取。

## 长期记忆

### 记忆类型

| kind | 含义 | 例子 |
| --- | --- | --- |
| `fact` | 客观事实 | 「我在做 AstrBot 插件」 |
| `preference` | 稳定偏好 | 「我喜欢简洁的回答」 |
| `event` | 已确认的事件/约定 | 「项目下周发版」 |

### 怎么写入

三条路径：

1. **用户显式**：说「记住：我习惯用 Python」→ 模型调用 `superai_remember`；
2. **后台自动抽取**：开启 `自动抽取事实` 后周期性调用模型抽取，见下；
3. **接口调用**：其他插件或代码可直接用 `plugin.memory.add(session, content, kind=...)`。

### 自动抽取的节流

抽取要额外调一次模型，所以有两层节流：

- **时间节流**：同一会话至少间隔 **180 秒**才抽一次；
- **内容指纹**：与上次抽取过的对话完全相同则跳过。

抽取失败（例如模型没输出合法 JSON）会**静默跳过**并推进进度，不会每轮重试。

### 记忆检索怎么打分

不引入向量库，用轻量方案：

```
相关性 = 3.0 × 子串命中
       + 2.0 × 字符 2-gram 重合率
       + 1.5 × 英文/数字词重合率
最终分 = 相关性 × (1 + min(权重, 5) × 0.1)
```

- 权重：命中一次 `+0.2`，上限 `5.0`；
- 检索命中后会给相关记忆加权，让「常用记忆」更稳；
- **一条都没命中时**会回落到「权重最高的若干条」，并把 `preference` 类排在前面
  —— 否则用户说「帮我写段文案」时，模型拿不到「用户喜欢简洁的回答」这类背景，
  长期记忆等于白存。

### 记忆怎么衰减

- 半衰期由 `记忆权重半衰期（天）` 控制（默认 30 天）；
- 衰减量取决于**距上次衰减过了多久**，而不是距上次命中过了多久 ——
  因此维护循环跑多少次结果都一致（幂等），不会指数坍塌；
- 权重低于 `0.2` 的记忆在下一次维护时被删除；
- 单会话最多保留 **400 条**，超出后按「权重、更新时间」淘汰。

后台维护每 600 秒跑一次（`MAINTENANCE_INTERVAL`），也可以
`/superai maintain` 手动触发（管理员）。

### 注入方式

记忆通过 `<long_term_memory>` 区块注入，位于本轮 user 消息的
`extra_user_content_parts` 里，并标记为**仅本轮有效**。

遵循「**没内容就不注入**」原则：`extra_user_content_parts` 里只要多一个 part，
provider 就会把纯字符串 user 消息升级成多模态 content 数组，自动前缀缓存随之失效。
因此没有摘要/记忆/知识库可注入时，SuperAI 完全不碰这个字段。

### 稳定性取舍

注入的上下文里包含这段稳定指令（写进 `system_prompt`，不随轮次变化）：

> 记忆与知识库可能已过时：与用户当前说法冲突时以用户当前说法为准，
> 并在必要时说明该记忆可能已过期。

## 数据文件

`data/plugin_data/astrbot_plugin_superai/`：

| 文件 | 内容 |
| --- | --- |
| `memory.json` | `{会话: [记忆条目...]}` |
| `summary.json` | `{会话: {summary, covered_rounds, total_rounds, history}}` |

写操作采用「临时文件 + 原子替换」，进程被杀不会写出半截文件。

## 管理指令

```
/superai memory list 20          # 本会话记忆 + 摘要
/superai memory search 编程语言   # 检索
/superai memory clear            # 清空本会话（管理员）
/superai memory stats            # 全局概览
```

## 已知局限

- 检索是 n-gram + 关键词相似度，**不是向量检索**，语义相近但用词不同的记忆可能命中不到
  （此时会走「权重兜底」通道）；
- 事实抽取依赖模型输出合法 JSON，抽取失败静默跳过；
- 记忆按会话隔离，**不跨群共享**；同一用户在不同群的偏好不会自动合并。
